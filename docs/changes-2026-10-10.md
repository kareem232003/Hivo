# Hivo update snapshot — 2026-10-10

This document describes the source changes present in the working tree relative to `c6d5026` when this snapshot was prepared. The new GitHub repository also retains the existing Git history. This is a publication snapshot, not a claim that every feature is production-ready. Existing implementation problems were left unchanged at the owner's request.

## Recursive planning and execution

- Added explicit worker contracts for inspection, implementation, verification, and integration. Contracts carry local objectives, the original goal, deliverables, inspection and mutation scopes, preservation constraints, verification expectations, and authority provenance. Child mutation scopes are constrained by the parent contract.
- Extended task splitting with stable provider-supplied subtask IDs, responsibilities, and declared source-evidence prerequisites. Implementation goals retain an implementation obligation through splitting and collection.
- Added verified workspace-source resolution for dependent workers, including placeholder resolution from prerequisite results, workspace path checks, and independently read source excerpts.
- Expanded memory evidence packs with relevant source snippets, repository commands, and correlated baseline command results.
- Added bounded recovery for malformed structured worker output and implementation results that only contain reports. Unusable implementation output blocks rather than counting as a completed code change.
- Added a provider-backed planning-evidence bootstrapper for the multi-plan factory, with canonical intent alignment, schema checks, invocation metadata, trace events, and saved raw/parsed outputs.

## Patch generation and validation

- Expanded the recursive edit-intent bridge to handle exact old/replacement text, unified diffs, patch artifacts, pseudo-patch conversion, generated deliverables, and implementation-readiness assessment.
- Normalize existing-file patch context against current workspace contents and build contextual surgical diffs with Git headers for creation and deletion.
- Distinguish auxiliary diagnostic/report artifacts from actionable implementation proposals. Validate candidate paths and patch applicability before passing proposals to the approval/apply workflow.
- Keep native application in Rust and use actual apply results and before/after Git snapshots for subsequent lifecycle decisions.

## Runtime lifecycle and plan mode

- Carry `thinkFirst` on individual turn requests from the desktop through the HTTP server to the runtime.
- Persist recursive plan state, raw tree nodes, and staged validation commands. Plan mode can stop at confirmation and resume the saved plan for implementation.
- Request baseline tests before recursive planning when command evidence is missing, expose `await_baseline_command`, and continue planning after a correlated execution result.
- Schedule post-apply validation commands and mark recursive plans implemented after an actual successful apply.
- Reworked completion decisions to account for unapplied/failed patches, pending commands, baseline evidence, and failed validation rather than automatically marking full-access runs done.
- Added local intent heuristics that override some provider inspection routes for explicit code-and-patch requests. This is recorded as an architectural concern in the README because project instructions require provider semantic authority.

## Provider budgets

- Share a provider-run budget across author/router/verifier/worker requests, embeddings, and Ollama retries.
- Added `HIVO_RUN_MAX_PROVIDER_CALLS` (default 24) and `HIVO_RUN_MAX_WALL_CLOCK_MS` (default 1,200,000 ms / 20 minutes).
- Cap provider request timeouts by the remaining budget and report consumed calls in telemetry. Each later turn receives a fresh budget.
- This bounds provider requests; it does not hard-cancel all non-provider orchestration work.

## Rust authority and desktop workflow

- Patch approval lookup now parses exact patch IDs and respects the latest approval or rejection instead of matching payload substrings.
- Added native command tests for approval decisions, application results, stale patches, and Git snapshots; exposed an in-memory database helper for tests.
- Added a 120-second foreground-command timeout with process-tree termination, collected output, and timeout diagnosis.
- Updated desktop plan-mode synchronization, baseline continuation, native patch rejection, session setup/error display, code-freshness messaging, and run status presentation.
- Strengthened fresh desktop launches to stop the runtime process tree on Windows and wait for its port to become available before restarting.

## Tests and acceptance tooling

Added coverage for native execution, patch context normalization, provider budgets, edit-intent bridging, recursive memory/source evidence, recursive lifecycle and plan mode, worker recovery, baseline continuation, semantic implementation output, worker contracts, and scope authority. Updated existing configuration, intent, approval, dispatch, provider-context, evidence-pack, and recursive bug tests and scripted test fixtures.

Added a real-provider buggy-calculator acceptance script. It currently contains machine-specific fixture/bridge paths and needs a running provider and those external fixtures; it was not run for publication.

## Publication and validation

The README ends with the current capability and validation map. Local validation logs are retained under `.agent_memory/publish-*.log` and remain uncommitted. The two modified `task_queue.sqlite` databases remain local because they hold volatile task/run state.

No implementation fixes were made while preparing this snapshot. Documentation and the Git publication metadata are the publication changes.
